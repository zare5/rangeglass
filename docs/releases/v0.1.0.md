Rangeglass checks whether a download URL actually serves correct HTTP byte ranges and conditional resume responses. It catches wrong chunks, changing content, truncated bodies, and servers that ignore Range or If-Range, using at most 7,175 application-read body bytes by default.

### Get started

- **Windows, no Python:** download `rangeglass-windows-x64.exe` and run it in PowerShell. This is an unsigned console executable.
- **Python 3.10+, no installation:** download `rangeglass.pyz` and run `python rangeglass.pyz --demo good`.
- **Install a package:** download the wheel and run `python -m pip install rangeglass-0.1.0-py3-none-any.whl`.
- **Source:** the `.tar.gz` distribution includes source, tests, and documentation.

```sh
rangeglass --demo good
rangeglass "https://example.com/large-file.bin"
rangeglass "https://example.com/large-file.bin" --json
```

Use your own direct download URL in place of the example. `--demo broken` demonstrates a wrong-range response and deliberately exits 1.

### Included

- Seven bounded probes with readable findings and suggested next steps.
- JSON schema v1 and meaningful exit codes.
- Query redaction, explicit redirects, and environment-sourced authentication headers.
- Good/broken/ignored-range local demos; no internet needed.
- English and Chinese documentation and MIT license.

### Boundaries

This is a small HTTP/1.1 diagnostic, not a downloader or a full integrity check. Only sampled overlaps are compared. Verify the completed file against a trusted checksum. Network buffering and CDN origin traffic are outside the application's byte cap.

`SHA256SUMS.txt` contains checksums for the release assets. They detect an incomplete or altered download relative to this release; they are not an independent publisher signature.
